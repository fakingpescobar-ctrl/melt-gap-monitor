# Melt Gap Monitor (prototype, no hardware)

[![Build APK](https://github.com/fakingpescobar-ctrl/melt-gap-monitor/actions/workflows/android.yml/badge.svg)](https://github.com/fakingpescobar-ctrl/melt-gap-monitor/actions/workflows/android.yml)

Android-приложение для отработки логики компьютерного зрения и калибровки **без аппаратной части**:
камера телефона смотрит на сопла и струи расплава, приложение находит их в кадре,
считает зазор в миллиметрах и показывает эмуляцию команд коррекции.

Репозиторий: `melt-gap-monitor`

## Как считается зазор

1. **Кромка сопла** — внутри ROI строится столбцовый профиль яркости (среднее по строкам ROI),
   сглаживается 3-точечным фильтром, берётся максимум |d/dx| — это самая сильная вертикальная
   граница. Позиция уточняется параболой по трём точкам (субпиксельно).
   Возвращается **левая/сильная кромка**, как в ТЗ.
2. **Струя** — в окне `jetAnchorX ± jetHalfWidth` для каждого столбца считается
   `(средняя яркость − средняя по окну) + 60 × доля ярких строк`. Так яркая вертикальная
   линия выигрывает у шумных бликов. Позиция уточняется центроидом по окрестности пика.
3. **GAP** = `|x_jet − x_nozzle|` в пикселях → умножение на масштаб `mm/px`.
4. **Сглаживание** — экспоненциальное среднее (α = 0.25), чтобы цифры не дёргались.

Масштаб `mm/px` не берётся из паспорта камеры: он определяется калибровкой по эталону
(кнопка **SCALE** → ввести реальную длину → тапнуть две точки). Хранится как «мм на всю ширину
кадра», поэтому переживает смену разрешения анализа.

Важно про зум: калибровка запоминает, при каком зуме она сделана, и масштаб автоматически
пересчитывается (`mm/px ∝ 1/zoom`). Но зоны ROI заданы в долях кадра, поэтому после сильного
изменения зума их нужно поправить — либо просто нажать **AUTO-CAL**.

## Эмуляция управления

Реальные реле/Raspberry Pi не подключены. По отклонению от цели (`TARGET 5.0 мм ± TOL`):

```
GAP 1: 3.8 mm  Δ-1.2   SHIFT RIGHT 1.20
GAP 2: 4.5 mm  Δ-0.5   HOLD
CMD: EMULATED (no relays)
```

`SHIFT LEFT/RIGHT` — это то, что ушло бы в реле; сейчас только текст на HUD.

## Управление

* **MODE: RUN / CALIBRATE** — режим работы или правки зон.
* **Зум** — двумя пальцами по картинке (pinch) или кнопками **−** / **+**.
  Диапазон ограничен возможностями камеры (на флагманах обычно 1–10×, с переходом на телеобъектив).
* В CALIBRATE: тащить внутри рамки — двигать, за уголки — менять размер,
  за штриховую вертикаль — двигать ось поиска струи.
* **AUTO-CAL** — одноразовый скан кадра. Работает в два захода:
  1. ищет **яркие вертикальные полосы** (струи) и ставит зону сопла слева от каждой;
  2. если полос нет — ищет **сильнейшие вертикальные границы** (кромки сопел).

  Результат честный: `AUTO-CAL: OK` либо `FAILED`, причина показывается тостом
  и пишется в лог (`AUTOCAL`). Статус трекинга отдельный — `TRACK: 2/2 NODES`.
* **RESET ZONES** — вернуть зоны по умолчанию.
* **SCALE** — калибровка масштаба по эталону.
* Ползунок **TOL** — допуск ±0.1…3.0 мм.

## Сборка

Локально (нужен JDK 17 + Android SDK 35):

```bash
./gradlew assembleDebug
# app/build/outputs/apk/debug/app-debug.apk
```

В облаке: workflow `.github/workflows/android.yml` собирает APK на каждый push
и кладёт его в артефакты Actions (`melt-gap-monitor-debug`).

## Установка на телефон

После успешной сборки APK публикуется в Releases (без логина):

```
https://github.com/fakingpescobar-ctrl/melt-gap-monitor/releases/download/latest/app-debug.apk
```

Открыть ссылку в браузере телефона → скачать → «Установить из этого источника»
(Android спросит разрешение для браузера — это нормально для APK вне Play Store).

## Логи и отладка

Без ADB логи видно прямо в приложении: кнопка **LOG** включает панель (последние 9 записей),
долгое нажатие очищает буфер.

Что пишется:

| Тег | События |
|---|---|
| `APP` | старт, версия, загруженные настройки, закрытие |
| `CAM` | разрешение, старт CameraX, rotation, ошибки |
| `VISION` | раз в секунду `nozzle/conf`, `jet/conf`, `gap px/mm`, ms на кадр; события `jet ACQUIRED/LOST` |
| `AUTOCAL` | успех (найденные зоны) или провал |
| `CAL` | калибровка масштаба |
| `UI` | режимы, сброс/правка зон, вкл-выкл панели логов |

Три приёмника одновременно:

1. **logcat**, тег `MeltGap` — если когда-нибудь подключишь телефон к ПК;
2. **кольцевой буфер** в памяти (400 записей) — рисуется поверх камеры;
3. **файл** `files/logs/meltgap.log` с ротацией на 512 КБ (`meltgap.1.log`).

## Ограничения прототипа

* Детекция опирается на контраст: тёмные сопла на светлом фоне — ок, «всё серое» — нет.
* Нет компенсации перспективы: камера должна смотреть примерно перпендикулярно плоскости сопел.
* Один масштаб на кадр: если сопла на разной глубине, для дальнего нужен свой эталон.
* Нет записи видео/логов замеров (следующий шаг).
